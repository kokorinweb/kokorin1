# restaurant-lead-parser

Собирает реальные компании России из публичных источников и определяет, у каких
из них **с высокой вероятностью нет собственного сайта** — то есть кому можно
предложить разработку. По умолчанию — общепит, но ниша переключается одним
словом: кофейни, барбершопы, стоматологии, автосервисы, юристы и ещё два десятка.

Главное отличие от «выгрузки каталога с пустым полем website»: пустое поле здесь
ничего не решает. Каждое заведение проходит до четырёх независимых проверок, и
результат сопровождается числом `website_confidence` (0–100) и текстовым
обоснованием, которое видно в Excel.

## Быстрый старт — две команды

```bash
./setup.sh       # venv, зависимости, .env, проверка ключей
./run.sh         # спросит город и нишу, выдаст лидов с контактами
```

На Windows — `setup.bat` и `run.bat`.

`./run.sh` без аргументов запускает диалог:

```
Город [Казань]: Казань

Какой бизнес ищем? Примеры:
  Общепит · Кофейни · Пекарни и кондитерские
  Салоны красоты · Барбершопы · Стоматологии
  Автосервисы · Юристы · Отели и гостиницы  …
  (можно вписать что угодно своими словами; Enter — весь общепит)

Ниша: барбершопы
Сколько компаний обойти [400]: 300
```

и печатает готовые карточки прямо в терминал:

```
  1. Барбершоп «Бородач»   [lead 83 · нет сайта на 85%]
     ул. Баумана, 15
     тел. +78435551122  |  VK https://vk.com/borodach
     рейтинг 4.8, 412 отз.
     карточка: https://osm.org/node/1
```

Можно и без диалога:

```bash
./run.sh "Казань"                  # весь общепит
./run.sh "Казань" "барбершопы"     # своя ниша
./run.sh "Москва" "кофейни" 2000   # ниша и лимит
```

Проверить, какие источники и ключи работают, можно в любой момент:

```bash
./.venv/bin/python main.py --check-keys
```

Команда делает по одному дешёвому запросу к каждому сервису и говорит, какой
максимум `website_confidence` тебе доступен при текущих ключах и хватит ли его
для порога экспорта. Если она сообщает «основной экспорт будет ПУСТЫМ» — заведи
`VK_SERVICE_TOKEN` (бесплатно, 10 минут) прежде чем запускать долгий сбор.

Ручной запуск, если нужны нестандартные параметры:

```bash
python main.py --city "Казань" --limit 500
# -> output/restaurants_no_website.xlsx
```

## 1. Установка

Нужен **Python 3.11+** (проверено на 3.11 и 3.12).

```bash
git clone <репозиторий>
cd restaurant-lead-parser
```

### Виртуальное окружение

```bash
python3 -m venv .venv

# Linux / macOS
source .venv/bin/activate

# Windows (PowerShell)
.venv\Scripts\Activate.ps1

pip install --upgrade pip
pip install -r requirements.txt

# для запуска тестов
pip install -r requirements-dev.txt
```

Playwright не требуется: все источники отдают данные обычным HTTP. Он добавляется
только если вы сами подключите источник, где без браузера не обойтись.


Минимально обязательное поле — контакт в `OSM_USER_AGENT`: правила OpenStreetMap

**Без единого API-ключа проект уже работает** — источник OpenStreetMap бесплатен
и покрывает всю Россию. Ключи повышают полноту данных и достижимую точность.

## 3. Где брать API-ключи

| Переменная | Сервис | Где получить | Что даёт | Тариф |
|---|---|---|---|---|
| — | **OpenStreetMap / Overpass** | ключ не нужен | базовый список заведений по всей России, контакты, соцсети, часы работы | бесплатно, ODbL |
| `YANDEX_PLACES_API_KEY` | **Яндекс, «Поиск по организациям»** | [developer.tech.yandex.ru](https://developer.tech.yandex.ru/services/) | самая полная база организаций РФ, телефоны, часы работы | бесплатный лимит + платные тарифы |
| `DGIS_API_KEY` | **2ГИС Catalog API** | [dev.2gis.ru](https://dev.2gis.ru/) | рейтинги и **количество отзывов**, рубрики, соцсети | демо-ключ + платные тарифы |
| `BRAVE_API_KEY` | **Brave Search API** | [brave.com/search/api](https://brave.com/search/api/) | проверка №2 (поиск сайта) | есть бесплатный тариф |
| `GOOGLE_CSE_API_KEY` + `GOOGLE_CSE_CX` | **Google Programmable Search** | [developers.google.com/custom-search](https://developers.google.com/custom-search/v1/overview) | проверка №2 | 100 запросов/сутки бесплатно |
| `SERPAPI_KEY` | **SerpApi** | [serpapi.com](https://serpapi.com/) | проверка №2 | платный, есть пробный лимит |
| `VK_SERVICE_TOKEN` | **VK API** | [dev.vk.com](https://dev.vk.com/) → приложение → сервисный ключ доступа | проверка №3: поле «сайт» в сообществе, размер аудитории | бесплатно |

Поисковый провайдер нужен **один любой** — порядок перебора задаётся
`SEARCH_PROVIDERS=brave,google_cse,serpapi`.

### Что будет, если ключей нет

| Конфигурация | Максимальный `website_confidence` | Последствие |
|---|---|---|
| только OSM, без поиска и VK | **78** (`MEDIUM`) | в основной экспорт (`>= 85`) не попадёт ничего |
| OSM + `VK_SERVICE_TOKEN` | **85** (`HIGH`) | основной экспорт работает |
| OSM + поисковый API + VK | **100** (`HIGH`) | максимальная надёжность |
| + Яндекс/2ГИС | то же | появляются рейтинги и отзывы, начинают работать `--min-rating` и `--min-reviews` и заметно точнее считается `lead_score` |

Это не перестраховка, а прямое следствие модели: без поиска и без чтения соцсетей
у нас просто нет доказательств, что сайта нет. Программа честно предупреждает об
этом при старте.

## 4. Команды запуска

```bash
# один город
python main.py --city "Казань" --limit 500

# несколько городов
python main.py --city "Казань,Самара,Уфа" --limit 1500

# регион целиком
python main.py --region "Краснодарский край" --limit 1000

# вся Россия (176 городов справочника, от крупных к средним)
python main.py --country RU --limit 10000

# полный пример из ТЗ
python main.py \
  --city "Москва" \
  --categories restaurant,cafe,gastropub \
  --min-rating 4.2 \
  --min-reviews 30 \
  --min-confidence 85 \
  --min-lead-score 60 \
  --exclude-chains \
  --limit 1000 \
  --output leads.xlsx

# top-100 / top-500 / top-1000 лидов
python main.py --city "Москва" --limit 3000 --top 100 --output top100.xlsx

# продолжить прерванный обход
python main.py --country RU --limit 10000 --resume

# перевыгрузить из уже собранной базы, ничего не собирая заново
python main.py --export-only --min-confidence 90 --top 500 --output top500.xlsx
```

## 5. Как определяется «без сайта»

### Проверка №1 — карточка бизнеса
Смотрим поле `website` источника и **классифицируем ссылку**. Если это отдельный
домен заведения — `HAS_WEBSITE`. Ссылка на VK, Zoon, Яндекс.Карты, Taplink,
Яндекс.Еду и т. п. сайтом не считается и переносится в соцсети/доставку.

### Проверка №2 — поиск по названию
Через разрешённый поисковый API формируются запросы:

```
"<название>" <город> официальный сайт
"<название>" <город>
<название> <тип заведения> <город>
```

Каждый результат прогоняется через `classify_url`. HTML-выдача поисковиков
**не парсится** — это нарушает их правила и упирается в защиту, которую мы не обходим.

### Проверка №3 — ссылки из соцсетей
* **VK** — официальный API: поле `site`, описание, статус сообщества.
* **Telegram** — публичная страница `t.me/<username>`, без авторизации.
* **Instagram** — **не парсится**: данные закрыты авторизацией. Ссылка только
  фиксируется как факт присутствия.

Профиль, который не удалось прочитать (нет `VK_SERVICE_TOKEN`, закрытый Instagram),
**не даёт прибавки к confidence** — утверждать «ссылки на сайт там нет» мы не вправе.

### Проверка №4 — проверка найденного домена
Домен из выдачи сам по себе ничего не значит. Мы открываем страницу и проверяем:
доступность, HTTP-статус, редиректы, `<title>`, наличие названия, телефона, города
и улицы в тексте, а также признаки домена-заглушки («домен продаётся», дефолтная
страница nginx, «сайт в разработке»).

Домен считается сайтом заведения, только если совпал **телефон**, либо название
(≥65 %) **и** город или адрес. Совпадения одного названия недостаточно:
одноимённый ресторан в другом городе — типовой ложный результат.

Дополнительно (`--no-domain-probe` отключает) проверяются вероятные домены,
собранные транслитерацией названия: `belyykrolik.ru`, `belyy-krolik.ru`,
`belyykrolik-kazan.ru`, `.com`, `.рф`. Кандидат проходит ту же проверку №4.

### Формула confidence

| Слагаемое | Баллы |
|---|---|
| сайта нет в карточке источника (база) | **+70** |
| поиск отработал и своего домена не нашёл | +15 |
| в выдаче только каталоги/карты/соцсети | +3 |
| перебор вероятных доменов ничего не подтвердил | +8 |
| соцсети **прочитаны**, ссылки на сайт нет | +7 |
| публичных соцсетей вообще не найдено | +3 |
| в поиске был похожий домен, но он не подтвердился | −12 |
| в соцсетях указан сайт, но он не подтвердился | −15 |

### Статусы

| Статус | Условие |
|---|---|
| `HAS_WEBSITE` | собственный сайт найден и подтверждён |
| `NO_WEBSITE_HIGH_CONFIDENCE` | confidence ≥ 85 |
| `NO_WEBSITE_MEDIUM_CONFIDENCE` | 70 ≤ confidence < 85 |
| `UNCERTAIN` | confidence < 70 либо домен из карточки мёртв |
| `CHECK_FAILED` | проверки не выполнились (сеть, 403, таймауты) |

В основной экспорт «без сайта» попадают записи с `website_confidence >= 85`
(порог меняется через `--min-confidence`).

## 6. lead_score

0–100, сортировка результата идёт **сначала по `lead_score`, затем по
`website_confidence`**.

**Повышают:** 50+/100+/200+/500+ отзывов, рейтинг от 4.0 и выше, активные соцсети
и заметная аудитория, телефон, e-mail, график работы, бронирование, доставка,
средний+ ценовой сегмент, несколько филиалов, полноценный формат заведения,
присутствие сразу в нескольких источниках.

**Понижают:** почти нет отзывов, нет рейтинга, нет телефона, нет адреса, почти
пустая карточка (заведение выглядит заброшенным), сетевое заведение
(сильнее — при `--exclude-chains`).

Типичный хороший независимый ресторан набирает 75–90; заброшенная карточка — 0–20.

## 8. Ограничения источников — читать обязательно

* **OpenStreetMap / Overpass.** Бесплатно, вся Россия, лицензия ODbL (при публикации
  производных данных требуется указание источника). Overpass — общий бесплатный
  ресурс: мы шлём не более одного запроса за раз с паузой 3 с. Главный минус —
  **нет рейтингов и отзывов**, поэтому `--min-rating` и `--min-reviews` на одном
  OSM отсекут почти всё. Полнота по крупным городам хорошая, по малым — хуже.
* **Яндекс, «Поиск по организациям».** Официальный API. Условия использования
  (лимиты запросов, требования к отображению и хранению данных) определяются
  вашим тарифом — соблюдение лежит на владельце ключа. Рейтинги через этот API
  не отдаются. Выдача ограничена ~500 объектами на запрос.
* **2ГИС Catalog API.** Официальный API, даёт рейтинг и число отзывов. Лимиты
  и правила — по вашему договору. Не более ~500 объектов на запрос, радиус ≤ 40 км.
* **Поисковые API.** Brave / Google CSE / SerpApi — платные или с суточными
  лимитами. При исчерпании квоты сервис отключается, а не долбится повторно.
* **VK API.** Сервисный ключ, метод `groups.getById` (поле `site`) и `groups.search`.
* **Telegram.** Читается только публичная страница `t.me/<username>`.
* **Instagram.** Не парсится принципиально: закрыто авторизацией.

**Чего проект не делает и делать не будет:** не обходит CAPTCHA, не обходит
авторизацию, не подделывает поведение браузера ради обхода антибот-защиты, не
парсит HTML-выдачу поисковиков и не игнорирует rate limits. При HTTP 403 источник
помечается как недоступный и исключается из прогона.

## 9. Rate limiting

Политика задаётся на каждый сервис в `config.py` → `RATE_LIMITS`
(одновременные запросы, минимальный интервал, число попыток, базовая задержка, таймаут).

| Сервис | Параллельно | Мин. интервал | Попыток |
|---|---|---|---|
| overpass | 1 | 3.0 с | 4 |
| nominatim | 1 | 1.1 с | 3 |
| yandex / dgis | 3 | 0.2 с | 3 |
| brave | 1 | 1.05 с | 3 |
| google_cse / serpapi | 2 | 0.3 с | 3 |
| vk | 1 | 0.35 с | 3 |
| проверка чужих сайтов | 16 | — | 2 |

Обработка ответов:

* **429** — повтор с экспоненциальным backoff, заголовок `Retry-After` уважается;
* **403 / 401 / 451** — сервис немедленно отключается до конца прогона (это отказ
  в доступе, а не повод пытаться ещё раз);
* **5xx, таймауты, разрывы** — повтор с backoff и джиттером;
* обнаружена CAPTCHA или антибот-заглушка — страница пропускается.

## 10. Кэш и resume

* **Кэш** (таблица `cache` в SQLite) хранит поисковые запросы (14 дней), проверки
  доменов (30 дней) и данные соцсетей (14 дней). Один и тот же запрос повторно не
  выполняется. Сброс — `--refresh`.
* Заведение не перепроверяется чаще, чем раз в `recheck_after_days` (45 дней).
* **Resume**: прогресс по каждой паре «источник + город» пишется в
  `harvest_progress`. После `Ctrl+C` или падения запуск с `--resume` продолжает с
  необработанных городов. Полный сброс — `--reset-progress`.

## 12. Ниши бизнеса и категории

По умолчанию собирается общепит. Параметр `--niche` (или ответ в диалоге)
переключает на другой бизнес — их около тридцати:

кофейни · пекарни · бары · салоны красоты · барбершопы · стоматологии ·
медицинские клиники · ветклиники · фитнес · йога-студии · отели · автосервисы ·
автомойки · юристы · бухгалтеры · агентства недвижимости · турагентства ·
курсы и школы · частные детсады · цветочные · аптеки · фотостудии · типографии ·
строительство и ремонт · мебель на заказ · организация мероприятий · тату-салоны ·
зоомагазины и груминг · клининг

Каждая ниша знает свои теги OpenStreetMap и свои слова для полнотекстового
поиска в Яндексе и 2ГИС. Незнакомый запрос («подологи», «кальянные») тоже
работает: он ищется по названию в OSM и полнотекстом в каталогах — результатов
будет меньше, программа об этом предупредит.

Стоп-слова подстраиваются под нишу: в общепите «аптека» в названии — повод
выбросить запись, в нише «аптеки» — норма. Общие стоп-слова (закрытые точки,
киоски, вендинг, названия без бренда) действуют всегда.

Внутри общепита категории включаются через `--categories`
(`--list-categories` покажет список): ресторан, кафе, гастробар, бар с кухней,
кофейня, пиццерия, суши-ресторан, семейный ресторан, грузинский, итальянский,
азиатский, стейк-хаус, пекарня-кафе, прочий полноценный общепит.

**Не собираются:** закрытые и несуществующие объекты (`disused:`/`was:`-теги,
`opening_hours=closed`), столовые при организациях, школьные и вузовские столовые,
комбинаты питания, фудтраки и мобильные точки, киоски и павильоны, продуктовые
магазины, вендинг, dark kitchen, точки только «на вынос» без зала, а также
карточки с родовым названием без бренда («Кафе», «Бар», «Шаурма»).

## 13. Дедупликация

Одно заведение из нескольких источников схлопывается в одну запись. Сравниваются
нормализованное название (fuzzy, RapidFuzz), адрес, номер дома, телефон,
координаты и домен. Блокировка — по геоячейкам ~500 м, префиксу названия,
телефону и домену, поэтому сравнений O(n·k), а не O(n²).

**Филиалы не сливаются**: точки дальше 350 м друг от друга или с разными номерами
домов остаются отдельными записями, даже при полностью совпадающем названии.

При слиянии поля берутся из источника с большим приоритетом
(Яндекс 40 > 2ГИС 35 > OSM 20), телефоны и соцсети объединяются, рейтинг берётся
у источника с большим числом отзывов.

## 14. Сетевые заведения

`--exclude-chains` исключает сети. Признаки: имя во встроенном списке федеральных
и международных сетей, тег бренда (`brand:wikidata` в OSM, `org` в 2ГИС), либо
`chain_branch_threshold` (по умолчанию 6) и более одноимённых точек в наборе.
Без флага сети остаются в выгрузке, но получают штраф к `lead_score` и помечены
колонкой «Сеть».
