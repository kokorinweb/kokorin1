# Osteria Bellini

Сайт итальянского ресторана с корзиной, ИИ-консультантом и Telegram-ботом. Один репозиторий,
один деплой, одно меню на все каналы.

## Что внутри

| Часть | Где | Что делает |
| --- | --- | --- |
| Сайт | `src/app` | Главная, меню с фильтрами, корзина и оформление заказа |
| ИИ-консультант на сайте | `src/components/ChatWidget.tsx` + `src/app/api/chat` | Отвечает по меню и **сам кладёт блюда в корзину** через tool use |
| Telegram-бот | `src/lib/telegram.ts` + `src/app/api/telegram` | Команды и тот же ИИ-консультант в личке |
| Заказы | `src/app/api/order` | Валидация, пересчёт цен на сервере, уведомление в рабочий чат |

Ключевая идея: **меню задано ровно в одном месте** — `src/lib/menu.ts`. Витрина, валидация
заказа, промпт ИИ и ответы бота читают его оттуда. Правила доставки так же живут только в
`src/lib/restaurant.ts`. Цены нигде не дублируются, поэтому разъехаться им негде.

## Запуск

```bash
npm install
cp .env.example .env.local   # и заполнить ключи
npm run dev                  # сайт на http://localhost:3000
npm run bot                  # в отдельном терминале: бот через long polling
```

Без `ANTHROPIC_API_KEY` сайт и корзина работают полностью, а чат честно отвечает, что
консультант недоступен. Без `TELEGRAM_BOT_TOKEN` заказы просто пишутся в лог сервера.

## Деплой

Сайт — обычное Next.js-приложение (Vercel, Docker, что угодно). После деплоя один раз
привязываем вебхук бота:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://ваш-домен/api/telegram&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

Отдельный процесс для бота в продакшене не нужен — он живёт в том же приложении.

## Чего здесь осознанно нет

Это работающий MVP, а не готовая к бою система. Не сделано:

- **Онлайн-оплата.** Заказ подтверждает менеджер, оплата курьеру или на кассе.
- **База данных.** Заказ уходит в Telegram и в лог; истории заказов нет.
- **Админка.** Меню правится в коде и деплоем.
- **Общее хранилище состояния.** Лимитер запросов и история диалога бота лежат в памяти
  процесса. На одном инстансе это работает; на нескольких репликах или в serverless
  контекст бота будет теряться — тогда нужен Redis/KV.
- **Бронирование столиков.** ИИ намеренно переводит такие вопросы на телефон.

## Безопасность и ИИ

- Браузер присылает только `itemId` и количество. Все цены и скидки считает сервер по `MENU` —
  подделать сумму через DevTools нельзя.
- Промпт запрещает выдумывать блюда, цены и акции; всё меню целиком лежит в контексте.
- Инструмент `add_to_cart` проверяет, что блюдо существует, до того как что-то попадёт в корзину.
- Вебхук Telegram защищён `secret_token`.
- `/api/chat` и `/api/order` ограничены по частоте запросов с одного адреса.
