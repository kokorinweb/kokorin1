# Два проекта в одном репозитории

| Адрес | Что это |
| --- | --- |
| `/` `/menu` `/cart` | Osteria Bellini — сайт ресторана с корзиной, ИИ-консультантом и Telegram-ботом |
| `/helix` | NUCLEA — скролл-сцена: прокрутка перематывает секвенцию кадров ДНК |

У каждого проекта свой root layout (`src/app/(site)` и `src/app/(experience)`), поэтому шапка,
корзина и чат ресторана не попадают на тёмную сцену, а сцена не тащит свои стили на сайт.

## NUCLEA — сцена на `/helix`

Прокрутка страницы перематывает 341 кадр, отрисованный на `<canvas>`, а надписи привязаны к
долям прогресса сцены и появляются ровно на нужных кадрах.

- **Почему кадры, а не `<video>`** — перемотка `currentTime` на мобильном Safari дёргается и
  отстаёт от пальца. Заранее загруженные кадры идут ровно. Цена — 5.9 МБ картинок под прелоадером.
- **За счёт чего плавно** — трёх вещей сразу: кадров вдвое больше исходных (интерполяция движения
  до 48 к/с), позиция догоняет скролл по экспоненте, а между двумя соседними кадрами идёт
  подмешивание, поэтому картинка непрерывна, а не щёлкает по кадрам. Кадры декодируются на этапе
  загрузки: иначе браузер распаковывает картинку прямо посреди прокрутки и роняет анимацию.
- **За счёт чего не мыло** — кадры апскейлены ×2 фильтром lanczos с лёгкой резкостью. Раньше
  браузер сам растягивал 568 пикселей на весь экран билинейно, отсюда и была каша.
- **Память** — распакованный кадр 1136×720 весит ~3 МБ, вся секвенция целиком это под гигабайт
  битмапов. На узких экранах и устройствах с малой памятью берём каждый второй кадр, разницу
  скрывает подмешивание.
- **Где что лежит** — сценарий и окна надписей в `src/lib/helix.ts`, движок в
  `src/components/helix/HelixScroll.tsx`, стили в `src/app/(experience)/helix.css`.
- **Появление блоков по скроллу** — один наблюдатель `src/components/ScrollReveal.tsx` на всю
  страницу, секции остаются серверными компонентами и размечаются атрибутом `data-reveal`.
- **Дрейф ленты и прочерчивание линий** — на CSS scroll-driven animations. Там, где браузер их
  не поддерживает, блоки просто стоят на месте, ничего не ломается.
- **`prefers-reduced-motion`** — сглаживание, дрейф и бегущая строка выключаются, текст остаётся.

Заменить ролик: положить новый в `public/helix` кадрами `f_001.webp…`, поправить `frameCount`
и размер кадра в `src/lib/helix.ts`. Текущие кадры нарезаны так:

```bash
ffmpeg -i исходник.mp4 \
  -vf "crop=568:360:0:0,\
       minterpolate=fps=48:mi_mode=mci:mc_mode=aobmc:me_mode=bidir:vsbmc=1,\
       scale=1136:720:flags=lanczos,unsharp=5:5:0.55:5:5:0.0,\
       eq=contrast=1.07:saturation=1.08" \
  -vsync 0 -c:v libwebp -quality 70 -compression_level 6 -preset picture public/helix/f_%03d.webp
```

`crop` убирает вотермарку в правом нижнем углу исходника. Ролик в 1080p подменяется без единой
правки в коде — только `scale` в команде и размеры в конфиге.

Компания NUCLEA и все медицинские цифры на странице вымышлены: это демонстрация анимации.

## Osteria Bellini — сайт ресторана

Сайт итальянского ресторана с корзиной, ИИ-консультантом и Telegram-ботом. Один репозиторий,
один деплой, одно меню на все каналы.

## Что внутри

| Часть | Где | Что делает |
| --- | --- | --- |
| Сайт | `src/app` | Главная, меню с фильтрами, корзина и оформление заказа |
| ИИ-консультант на сайте | `src/components/ChatWidget.tsx` + `src/app/api/chat` | Отвечает по меню и **сам кладёт блюда в корзину** через tool use |
| Telegram-бот | `src/lib/telegram.ts` + `src/app/api/telegram` | Команды и тот же ИИ-консультант в личке |
| Заказы | `src/app/api/order` | Валидация, пересчёт цен на сервере, уведомление в рабочий чат |

Ключевая идея: **меню задано ровно в одном месте** — `src/lib/menu.ts`. Витрина, валидация
заказа, промпт ИИ и ответы бота читают его оттуда. Правила доставки так же живут только в
`src/lib/restaurant.ts`. Цены нигде не дублируются, поэтому разъехаться им негде.

## Запуск

```bash
npm install
cp .env.example .env.local   # и заполнить ключи
npm run dev                  # сайт на http://localhost:3000
npm run bot                  # в отдельном терминале: бот через long polling
```

Без `ANTHROPIC_API_KEY` сайт и корзина работают полностью, а чат честно отвечает, что
консультант недоступен. Без `TELEGRAM_BOT_TOKEN` заказы просто пишутся в лог сервера.

## Деплой

Сайт — обычное Next.js-приложение (Vercel, Docker, что угодно). После деплоя один раз
привязываем вебхук бота:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://ваш-домен/api/telegram&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

Отдельный процесс для бота в продакшене не нужен — он живёт в том же приложении.

## Чего здесь осознанно нет

Это работающий MVP, а не готовая к бою система. Не сделано:

- **Онлайн-оплата.** Заказ подтверждает менеджер, оплата курьеру или на кассе.
- **База данных.** Заказ уходит в Telegram и в лог; истории заказов нет.
- **Админка.** Меню правится в коде и деплоем.
- **Общее хранилище состояния.** Лимитер запросов и история диалога бота лежат в памяти
  процесса. На одном инстансе это работает; на нескольких репликах или в serverless
  контекст бота будет теряться — тогда нужен Redis/KV.
- **Бронирование столиков.** ИИ намеренно переводит такие вопросы на телефон.

## Безопасность и ИИ

- Браузер присылает только `itemId` и количество. Все цены и скидки считает сервер по `MENU` —
  подделать сумму через DevTools нельзя.
- Промпт запрещает выдумывать блюда, цены и акции; всё меню целиком лежит в контексте.
- Инструмент `add_to_cart` проверяет, что блюдо существует, до того как что-то попадёт в корзину.
- Вебхук Telegram защищён `secret_token`.
- `/api/chat` и `/api/order` ограничены по частоте запросов с одного адреса.
