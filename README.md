# НОРИ

Сайт японского ресторана: меню, корзина, **бронирование столика по схеме зала**,
предзаказ блюд к приходу гостя, ИИ-консультант и Telegram-бот. Один репозиторий,
один деплой, одно меню на все каналы.

## Что внутри

| Часть | Где | Что делает |
| --- | --- | --- |
| Витрина | `src/app/page.tsx`, `src/components/home` | Главная: популярное, сеты, шеф, интерьер, акции, отзывы, сертификаты, контакты |
| Меню | `src/app/menu` + `src/components/MenuBrowser.tsx` | 10 категорий, 6 фильтров, карточки с составом и весом |
| Бронирование | `src/app/booking` + `src/components/BookingWizard.tsx`, `FloorPlan.tsx` | Дата → гости → время → **клик по свободному столу на схеме** → контакты |
| Предзаказ | экран после брони + `src/components/CartView.tsx` | Блюда к времени подачи: сели в 20:00 — роллы на столе к 20:05 |
| Корзина | `src/app/cart` | Самовывоз (−10%) или подача к забронированному столику |
| ИИ-консультант | `src/components/ChatWidget.tsx` + `src/app/api/chat` | Отвечает по меню, **сам кладёт блюда в корзину** и **реально смотрит свободные столы** |
| Telegram-бот | `src/lib/telegram.ts` + `src/app/api/telegram` | Тот же консультант в личке; брони и заказы падают в рабочий чат |

Ключевая идея: **меню задано ровно в одном месте** — `src/lib/menu.ts`. Витрина, фильтры,
валидация заказа, промпт ИИ и ответы бота читают его оттуда. Правила заведения живут в
`src/lib/restaurant.ts`, зал и слоты — в `src/lib/booking.ts`. Цены и часы работы нигде не
дублируются, поэтому разъехаться им негде.

## Запуск

```bash
npm install
cp .env.example .env.local   # и заполнить ключи
npm run dev                  # сайт на http://localhost:3000
npm run bot                  # в отдельном терминале: бот через long polling
```

Без `ANTHROPIC_API_KEY` сайт, корзина и бронирование работают полностью, а чат честно
отвечает, что консультант недоступен. Без `TELEGRAM_BOT_TOKEN` заявки пишутся в лог сервера.

## Дизайн-система

Токены — в `src/app/globals.css`, менять цвета нужно только там.

- **Суми** `#0a0a0c` — тушь, основной фон. **Васи** `#f4efe6` — рисовая бумага, светлые
  секции («Почему НОРИ», отзывы). Чередование задаёт ритм длинной страницы.
- **Сюдзи** `#ff5a2b` — киноварь, единственный акцент. Текст на кнопках тёмный (`#0a0a0c`),
  а не белый: белый по киновари даёт контраст 3.2:1 и не проходит WCAG AA.
- Шрифты: Playfair Display (заголовки), Manrope (интерфейс), JetBrains Mono (рубрики,
  цены, слоты времени), Noto Serif JP (кандзи в декоре).
- Движение — свой `Reveal` на IntersectionObserver, 30 строк вместо 60 КБ библиотеки.
  Класс `js` ставится инлайновым скриптом до первой отрисовки: **без JS страница видна
  целиком**, а `prefers-reduced-motion` полностью выключает анимацию.

### Картинки блюд

Фотографий в репозитории нет. Вместо серых заглушек каждое блюдо рисуется вектором —
`src/components/DishArt.tsx`: ролл в разрезе, нигири в профиль, пиала, доска, бокал.
Форму задаёт `art.kind`, цвета — `art.colors`, обёртку (нори или рыба снаружи) — `art.wrap`.

Появились фото — достаточно положить файл в `public/` и указать `image: "/photo/....jpg"`
у блюда в `src/lib/menu.ts`. `DishMedia` сам покажет фото вместо вектора, вёрстку менять не надо.

## Как устроено бронирование

1. `slotsForDate` строит слоты от открытия до «закрытие минус 90 минут», шаг 30 минут.
2. `tableAvailability` отдаёт состояние всех 20 столов на дату и время.
3. Клиент рисует схему и даёт кликнуть по свободному столу.
4. `validateBooking` **перепроверяет всё на сервере** — между отрисовкой схемы и нажатием
   кнопки стол мог уйти. Тогда возвращается 409 и схема обновляется.
5. Код брони (`NORI-8F3K`) кладётся в `localStorage`, и корзина подставляет его сама.

## Чего здесь осознанно нет

Это работающий MVP, а не готовая к бою система. Не сделано:

- **База данных.** Брони лежат в памяти процесса (`src/lib/booking.ts`), заказы уходят в
  Telegram и в лог. После рестарта брони пропадут, а на нескольких репликах разъедутся.
  Это первое, что нужно заменить: `findBooking`/`saveBooking` → Postgres или Redis.
- **Демо-занятость зала.** Функция `demoOccupancy` детерминированно «занимает» часть столов,
  чтобы схема выглядела живой без базы. В продакшене удаляется целиком.
- **Онлайн-оплата.** Заказ и сертификат подтверждает менеджер, оплата на месте.
- **Админка.** Меню, акции и тексты правятся в коде (`src/lib/menu.ts`, `src/lib/content.ts`).
- **СМС-подтверждение брони.** Экран успеха обещает СМС — нужно подключить провайдера.
- **Настоящая карта.** В контактах схематичная SVG-карта; заменяется одним `<iframe>`
  Яндекс.Карт с ключом.
- **Общее хранилище состояния.** Лимитер запросов и история диалога бота — в памяти процесса.

## Безопасность

- Браузер присылает только `itemId` и количество. Все цены и скидки считает сервер по `MENU` —
  подделать сумму через DevTools нельзя.
- Бронь проверяется на сервере повторно: дата, слот, вместимость стола и его занятость.
- Промпт запрещает выдумывать блюда, цены, акции и свободные столики; свободное время
  ассистент узнаёт только инструментом `check_tables`, который читает те же данные, что и сайт.
- Вебхук Telegram защищён `secret_token`.
- `/api/chat`, `/api/order`, `/api/booking`, `/api/booking/lookup` и `/api/certificate`
  ограничены по частоте запросов с одного адреса.

## Деплой

Обычное Next.js-приложение (Vercel, Docker, что угодно). После деплоя один раз привязываем
вебхук бота:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://ваш-домен/api/telegram&secret_token=<TELEGRAM_WEBHOOK_SECRET>"
```

Отдельный процесс для бота в продакшене не нужен — он живёт в том же приложении.
